# Datasets — provenance, legality, quality, citation

All files in `data/raw/` are verified by SHA-256 every time the pipeline runs (`bdx/data.py::fetch`).
If a file is missing it is downloaded again; if its checksum differs the run stops, so every result is
traceable to byte-identical data.

## How each was obtained
* **credit** — official source: UCI Machine Learning Repository, https://archive.ics.uci.edu/dataset/350
  (DOI 10.24432/C55S3H). The file used is a CSV conversion of the official `.xls` (identical records,
  header row normalised), downloaded from the mirror listed in `bdx/data.py`.
* **telco** — official IBM GitHub repository `IBM/telco-customer-churn-on-icp4d`, `data/Telco-Customer-Churn.csv`.
  `TotalCharges` contains 11 blank strings (new customers); they are imputed with the median.
* **elec2** — scikit-multiflow `streaming-datasets` repository (`elec.csv`), the normalised version of
  Harries (1999) used throughout the drift literature. Rows are kept in time order (natural stream).
* **digits** — `sklearn.datasets.load_digits()`; a local copy ships with scikit-learn.
* **sea** — `river.datasets.synth.SEA` and `ConceptDriftStream`.

## Legality and ethics
All data are public, licensed for research and contain no direct identifiers (Telco customer IDs are
synthetic and are dropped). Credit records are anonymised by the original authors. No personal data are
collected by this project.

## Quality and structure
* No missing values except Telco `TotalCharges` (0.16 %, median-imputed).
* Class imbalance is moderate (22-42 %); accuracy is therefore reported together with a reference value
  measured on a held-out calibration set, and drift is judged against that reference.
* Categorical columns are one-hot encoded (drop-first); continuous columns are standardised with
  statistics of the training split only (no leakage into calibration or stream).

## Original contribution: semi-synthetic drift streams
Static real datasets do not tell *when* a drift happens, so no lead time could be measured. We therefore
**generate drift streams by controlled transformation of real records** (see `bdx/drift.py`):

* population = all records of the dataset; training/calibration samples drawn without replacement;
* the stream is sampled from the held-out records (with replacement when the pool is smaller than the stream);
* drift starts at t0 = 2500 and ramps linearly over 1500 samples;
* four mechanisms with known ground truth (none / covariate / sensor / real) and recorded drifted features.

This makes the data contribution reproducible on *any* tabular dataset: `bdx.data.load_csv(path, target)`
followed by `bdx.drift.build_stream(...)`.
